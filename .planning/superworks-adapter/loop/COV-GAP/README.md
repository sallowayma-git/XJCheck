# COV-GAP：端子排 / 端子 / 导线线组覆盖缺口分析（round12）

只读分析。数据：`.tmp/superworks_round12_full/p000..p076`（77 个项目，1745 张 DWG 的冻结回放）。未读取 `.tmp/superworks_round13_full`，未修改 `src/`、`tests/`，未使用 git。冻结 DXF 由 `corpus_manifest.json` 指向，仅读取。

## 0. 结论摘要

1. **严格口径实测 57.3%**（端子/装置端子，47380 / 82680）。你给的“约 63%”在 round12 和 round3 上都复现不了：沿用 `round3_f5.json` 的口径，round3 为 57.5%；63% 只在 N2604 合同子集里出现（63.0%）。`report.md` 的 94.28% 来自另一次验收运行，不能与本回放比较。以下所有数字都以本回放实测为准。
2. **端子排行的左、右连接 100% 被消费**：20806 个连接（左 10247、右 10559）每个都挂着一条 pass 的 table_mapping 配对。`_2` 并接槽位在全语料为 0（已用原始 DXF 复核，见 §7）。端子排行本身不是缺口。
3. **真正的缺口有三块**：
   - 端子排的**跨页去向文字**：43596 个条目（唯一文字 33453）只有 47.7% 被消费。未消费的 22817 个全部是“未定义<句柄>:<端口>_<页>”占位文字，其中 20339 个能解析到目标页上一个带身份的 SW 端口；`cross_page_refs` 在全 src 里只被解析和存储，没有任何配对代码读取它。
   - **元件引脚没有身份**：端子导线的另一端落在元件图形内部引脚上（内部元件端口 / 圆形引脚标记），这些引脚无身份，导致端子无法形成身份配对（最大的单一桶，17333）。
   - **值形态不一致**：review 配对的侧值去掉了设备侧前缀（如 `717` 对 SW 身份 `1n717`），1602 个严格端子因此不计消费。这是最便宜的修复。
4. **建议优先的 3 个切片**：S1 跨页去向链接（严格口径上界 +14.2 个百分点）；S2 SW 身份前缀规范化加 D1d 台账修正（+1.9 个百分点，改动最小）；S3 元件引脚身份（上界约 +23 个百分点，风险最高，需先做只报告的候选）。详见 §6。

## 1. 口径

- **严格口径（沿用）**：来自 `src/dwg_audit/report/superworks_artifacts.py`。eligible = 端子/装置端子 且有导线接触且标签已解析；consumed = 非 discard 生产配对中，SW 证据的 `port_ids` 命中该端口，且侧值与端口身份（casefold）相等。
- **层 a（端子排行）**：每行的左侧（外部接线）和右侧（内部接线）各算一个对象（XDATA 中句柄非 0 的槽位，与 `connections` 一致）；`_2` 并接按 XDATA 槽位计数。覆盖 = 该连接文字被至少一条非 discard 配对引用，且配对两侧身份非空（严格）；仅挂接算宽口径。
- **层 a2（端子排去向文字，即 `potentials`）**：这是用户列出的“端子排行去向文字未解析”桶对应的对象层，单独列出。覆盖 = 文字被非 discard 配对引用。
- **层 b（SW 端子）**：严格口径（端子/装置端子）。其他类别（内部元件、线圈、接地、接插件）单列为宽口径，覆盖 = 被非 discard 配对的 SW 证据引用（任意值）。
- **层 c（二次原理图导线线组）**：每个线组两端（start/end），若端点处存在非 discard 配对侧值（坐标在 2 单位内）或被接受的候选文字（2.5 单位内），则记为已解析。
- **层 d（元件接线图/背板页）**：这些页上没有带导线接触的端子类 SW 端口（只有接地类），因此 d 层按文字定义：元件接线图、背板接线图、背板表格型图上、数字型、且不在 out_of_scope 中的文字；覆盖 = 判定为 resolved 且被非 discard 配对消费。
- **未覆盖对象的主桶**：端口先按本端问题归类（P0 页面不在审计范围、P1 本端身份未解析、P4 SW 引用存在但值不一致），其余按另一端类型归类（O 类）；“同组配对均为 discard”（P3）和“同组配对未引用本端口”（P5）作为标签保留。
- 字段名与中间文件位于会话 scratchpad（`covgap/`），不在仓库内。

## 5. 每桶的修复思路、收益与风险

所有收益数字都是上界，假设每个对象都能被正确配对。修复都不得按项目、数值或句柄特判，也不得整体豁免 SuperWORKS 来源。

| 桶 | 值得做？ | 通用修复思路 | 可提升的对象数 | 风险（伪连接 / 误报） |
|---|---|---|---|---|
| O3 对端为内部元件端口 | 值得，但需设计 | 为元件内部引脚生成“元件标号 + 引脚号”身份：标号取自元件块旁标签文字，引脚号取自 SW `port_number` 或块内数字；仅当同页内标号与引脚号唯一时启用，作为 SW 证据配对 | 17333（严格端子 +21.0 个百分点） | 高：重号、同名多实例、标号归属错误会制造伪连接；必须有同页唯一性与互为对端校验 |
| X2 跨页目标未消费 | **值得，优先** | 用 `cross_page_refs`（句柄 + 端口号）在同项目内定位目标端口；当目标身份与同行端子排连接身份相等、且目标在项目内唯一时，建立跨页 SW 证据配对；状态沿用既有 pass/review 规则 | 11706 个严格端子（+14.2 个百分点上界） | 中：同身份多页重复（已有 `competing_physical_port_identities` 先例）；目标若已被另一配对消费，会变成多对一，必须交给既有多对一规则，不能直接放行 |
| X1 目标已消费、链路未建 | 暂不做，仅报告 | 只在有独立证据（XDATA 句柄唯一对应）时建链，并视为二次证据，不改变既有配对 | 严格覆盖增量为 0（目标已消费）；身份相等的仅 1612 | 高：命名体系不同，身份规则会误连。建议只作候选报告，不进覆盖率 |
| O10 对端无实体无文字 | 与 O3 合并 | 元件引脚身份（同 O3）；框线/表格线先按非导线分类，再参与端点判定 | 最多 8357，多数需要 O3 的身份 | 中：把框线当导线会制造伪连接 |
| D1a 元件内部引脚号被拒 | 做口径修正，不做连接 | 在元件接线图的覆盖分母中把块内引脚号单列，不计入外部端子覆盖；确有外部导线的，再交给 O3 规则 | 分母减少 4068（不增加连接） | 低（口径改动须在报告中说明） |
| X3 跨页目标设备无 SW 符号 | 不做 SW 修复 | 只能由文字侧设备名与端子排去向做独立配对，非 SW 扩展 | 无法由 SW 修复 | 低（只报告） |
| P4 SW 引用存在但值不一致 | **值得，最便宜** | 比较时允许剥离设备侧前缀（如 `1n`）：仅当前缀在同页同设备内唯一，且剥离后与端口身份对应唯一时视为相等。P4 的 1838 个分解为：前缀被去掉 1602（全部为 review，另 9 个为 pass wire_component_mapping）；SW 端无 value 95；配对侧为空 47；身份确实不同 94 | 1602 个严格端子（+1.9 个百分点）；其余 236 个需另议 | 低-中：必须限定同页同设备；需回归检查多对一与 competing identity |
| O7 对端文字已接受但未成对 | 并入 O3 | 把已接受的裸引脚号与旁边元件标号组合为完整身份后参与配对 | 最多 1628（与 O3 有重叠） | 中：裸数字多义，必须有标号唯一性 |
| D1d 台账未挂接 | 值得，低风险 | 当 component_mapping 的 evidence 引用了该文字，把该文字挂到该映射的 consumed_by（不改变配对） | 288（层 d 覆盖 +1.2 个百分点） | 低 |

## 6. 建议优先的切片

1. **S1 跨页去向链接（X2，并修 D1d 台账）**：`cross_page_refs` 已解析、没有消费方，是最确定的杠杆。严格端子覆盖上界 57.3% → 71.5%（+14.2 个百分点，其中 11706 个为未覆盖严格端子）。先在 round12 上做只报告的候选，统计身份相等的 5718 条与其他候选的冲突，再决定是否放行。
2. **S2 SW 身份前缀规范化（P4，附带 D1d 台账修正）**：最小改动，1602 个严格端子（+1.9 个百分点），风险可控。可以最先做，作为回归基准的一个小步。
3. **S3 元件引脚身份（O3 + O7 + O10 的共同根因）**：收益最大（上界约 +23 个百分点），风险也最高。应先做只报告的候选：生成“元件标号 + 引脚”身份，抽样目视核对精度（建议至少 30 例），达到门槛后再启用。

## 7. 核对与注意事项

- **原始 DXF 复核 `_2` 并接**：在 12 个项目、242 个 DXF 中，`LDDZ_LEFTTEXT_HANDLE_2`、`LDDZ_RIGHTTEXT_HANDLE_2`、`LDDZ_LEFT_FENGEHANDLE`、`LDDZ_RIGHT_FENGEHANDLE` 的实体用法全部为 0；左、右槽位分别有 1756、1228 个非零值，与读取结果一致。所以 `_2` 并接在本语料中确实没有对象，不是读取器丢失。
- **去向文字的字高**：未覆盖的 22817 个占位文字全部为字高 1.0 的 TEXT（layer 0，内容“未定义…”）；已覆盖的 10636 个字高为 3.0。占位文字在整页缩放时几乎看不见（B2 样例中未能直接看到），但它是可读的 TEXT 实体。
- **去向文字的去重**：43596 个条目对应 33453 个唯一文字，其中 10143 个被两行共享，共享的全部已覆盖。X 桶的计数是唯一文字计数，没有重复。
- **D1d 抽样偏差已修正**：早期只看前 40 个项目得到“0 个被非 discard 映射引用”，全语料结果为 288 / 1382。
- **层 c 的分母含非导线**：线组候选中混入了表格边框线和文字块分隔线（目视 3 例中 2 例）。`wire_candidate_score` 无法区分（见 §2.4）。因此层 c 的“两端都没有”是高估，真实导线覆盖需要先做导线分类。
- **目视样例数量有限**：每桶 3 例，判断为定性。未覆盖桶的规模用全量计数，目视只用于解释根因。
- **端口与文字的对端判定是几何近似**：容差为 1.0（端口）、1.5（端子排连接点）、0.3（线段端点），对端取离接触点较远的线段端点。T 形接入与弯折线可能被误判为“对端悬空”（O10），这一点在 B4 样例中可见。
- 没有修改 `src/`、`tests/`，没有 git 操作。仅使用了 round4 的渲染模块（只读导入，导入时生成的 `__pycache__` 已删除）。
