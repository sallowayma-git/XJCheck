## 1. 判定规则（`src/dwg_audit/audit/superworks_device_internal.py`）

- **eligible 装置端子**：类别为 `装置端子`，有导线接触，标签已解析（与 `superworks_artifacts` 的 eligible 定义一致）。
- **装置端子身份 = 标签 + 脚号**：标签取 `label.normalized`（如 `1n`、`2-1n`），脚号为身份去掉标签后的部分（`1n705` 的脚号为 `705`）。身份为空（脚号未解析）的端子不建链。
- **导线 = SW 线组**：一条导线是其 LINE 段所在线组的并集（`wire_keys_from_lines`，与 `superworks_extractor` 的线组一致）。若只按单段句柄判定，多段导线的另一端会被漏掉或误判。
- **建链条件**：端子的导线中**恰有一条**满足下列条件：该导线在同一文件上只连接两个端口，即本端子与一个 `内部元件` 或 `线圈` 引脚；且该元件的标签（规范化后、大小写不敏感）**等于**端子的装置标签。
- **不建链**（按导线计数，见第 3 节）：导线上没有其它端口（单端）；导线连接多个端口（多端线组）；另一端为端子、装置端子、接地或其它类别；元件标签与装置标签不同，或只是相关（`1-1n` 与 `1n`）；端子有多条满足条件的内部导线（有歧义）。
- **PCL 佐证**：存在来源为 PCL 的 `sw_wire_routes` 记录，其 LOCAL 端身份与端子身份相同（即逻辑端号等于脚号尾号，且属于同一装置）。佐证只作标注，不影响建链。
- 元件的身份不参与判定。Top 8 中的第 8 类（端子接无身份的内部元件）不属于装置端子，不建链。

## 8. 复现

工具位于 `tools/`：

- `compare_runs.py <round18> <run> [--projects ...] [--full] --json out.json`：配对与 issue 比对（`--full` 为全列），四口径覆盖。
- `stats_and_gaps.py <run> <out_dir> --links-parquet <path>`：统计、排除原因、Top 缺口与开口端探针（输出 `stats.json`、`gaps.json`）。
- `check_links_match.py <round_dir> <run_dir>`：用最终模块在另一轮输入上重算链接，与运行输出逐条核对（本轮结果见 `links_match_round18_inputs.json`，12847 条全部一致）。
- `sample_render.py <links.parquet> <run> <corpus_manifest.json> <out_dir>`：分层抽样与渲染（输出 `png/`、`samples.json`）。

## 9. 局限

- 链接依赖元件带 LD_SYMB2 元数据并能解析标签。无元数据的元件引脚不在链接范围内（Top 8 第 1 类）。
- PCL 佐证比较的是身份相等（逻辑端号 + 装置标签），不做前缀或数值推断。
- `link_id` 在项目内唯一，跨项目不唯一（文件 id 在各项目内重复），外部引用必须同时带上项目。
- 目视为单人判定，清晰度分层是主观判断。
- 链接只计覆盖，不进入 issue，因此不会新增发现的问题。它们只减少端子的未覆盖计数。
