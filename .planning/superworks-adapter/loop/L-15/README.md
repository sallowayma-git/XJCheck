# L-15：nearest 端口能否统一改为「标签+端口号」
范围：`.tmp/superworks_round7_full` 全部 77 项目，26,823 个 SW 连接线端口。只读，未改 src/，未全量回放，未提交。

## 0. 结论
- **不统一。** 独立证据下，当前 nearest 身份一致率 83.9%，「标签+端口号」仅 2.2%。统一会使 4,786 个一致身份变为不一致，只修正 124 个。
- **可做窄修复：X 前缀端口名。** 246 个 nearest 端口的 TERMPOINT 号为 `X1`、`X19` 等，pin 文字只剩数字，身份丢了 `X`。可验证的 141 个全部符合「标签-X#」，0 个符合现行身份。
- N2 的 (c) 64% 是存在性检查，同标签错位对照也有 73%，说明它对端口号无区分力，不能作依据。

## 2. nearest 与标签+端口号不同且可验证（n = 5,703）

| 独立证据正确的形式 | 数量 | 比例 |
|---|---:|---:|
| nearest（当前） | 4,786 | 83.9% |
| 仅「标签+端口号」（如 1ZKK11） | 124 | 2.2% |
| 仅「标签-端口名」（如 K742-X19） | 141 | 2.5% |
| 仅标签（器件级） | 283 | 5.0% |
| 都不匹配 | 369 | 6.5% |

124 个集中在 p070（84）、p051、p075（各 12），这些器件排行写作无连字符形式（如 `6SDn10`），属项目内命名约定。revoked 端口的标签+端口号 96.6% 一致，nearest 文字形式 0%，N1 回落方向正确。

## 3. 统一改用的代理影响
- 改 9,737 个 nearest/reference 端口的值；可验证中净损失 4,662（4,786 失 / 124 得）。共享身份 88 → 112，一身份对多去向 4 → 28。
## 4. X 前缀窄修复
- 246 个端口（p029 64、p031 64、p030 55、p004 18、p028 18、p035 18、p000 9）；可验证 141 个，dash 141/141 一致，nearest 0/141。
- 代理：改 246 个值，共享身份 88 → 88，无新增冲突。残余 154 个（如 `PWR4` 对 `4`）本轮不处理。

## 6. 限制
- wire 检查依赖 pair 覆盖，「都不匹配」不等于身份错误；对端只比文字，不证明端口号归属。代理影响不是规则重跑，X 修复需定向回放 7 个项目确认。
## 7. 修改点（建议，未改代码）
- `superworks_semantics.py:398-400`：nearest 身份组装。对 nearest 且端口号为 `[A-Za-z]+\d+`、数字与 pin 规范值相同者，endpoint 取 `label + "-" + 端口号`。
- `superworks_semantics.py:410-415`：F4c 已生成 `endpoint_aliases`（如 `K741-X1`），但连接线匹配只比较 endpoint。
- `superworks_semantics.py:570`、`:664-680`：连接线标签取端口身份；`superworks_extractor.py:816`、`:842`：component_mapping 左值。
