# L-11 SuperWORKS 适配层端到端耗时测量

## 方法
- 基线：`baseline_src`；当前：`round7_full_src`。回放脚本 `replay.py`，`--workers 1`，8 个项目（p000 p024 p030 p044 p050 p061 p070 p075）。
- 交替顺序各跑 2 次：基线、当前、基线、当前。开始前确认无其他 python 进程。四轮均 COMPLETE，无失败。
- 耗时取两次中位数（两次取值的均值）。阶段来源：`complete.json` 的 `elapsed_seconds`、`stage_seconds.extract`、`stage_seconds.recognition`；其他 = 总耗时 − 抽取 − 识别，即转换 + 审计 + 写出的合并值。
- 注意：`runtime_profile.json` 不含阶段耗时字段，无法按转换/审计/写出拆分。
- SW 模块自身计时取自当前版本 `findings/superworks_summary.json` 的 `timing` 字段（extraction_seconds、recognition_seconds）。
- 单轮整体墙钟：基线 126.0 / 126.3 s，当前 142.0 / 142.0 s；按两轮分别计算的增幅为 12.7% 与 12.5%。

## 合计阶段耗时（秒）
- 基线：抽取 82.80，识别 15.55，其他 27.80。
- 当前：抽取 87.38，识别 22.83，其他 31.78。
- 当前版本 SW 模块计时合计：抽取部分 4.88，识别部分 6.89，共 11.77 s。约占总增量 15.84 s 的 74%。

## 结论
- 总增幅 12.6%，**达标**（验收目标 ≤20%）。不需要 cProfile，未执行第 4 步。
- 增量主要来自识别阶段（+7.3 s，其中 SW 识别计时 6.89 s）和抽取阶段（+4.6 s，其中 SW 抽取计时 4.88 s）。其他阶段增量约 4.0 s。
- 当前版本 pairs 数普遍增加（合计 +20% 以上，p070 达 +51%），issues 数也有变化（如 p070 由 4 降为 0，p061 由 1 升为 4）。因此部分识别增量来自新增识别结果，而非纯粹的计算开销。耗时比较只在输出规模不同的前提下成立。
- 热点：SW 识别计时在 p061 中为 2.44 s，是所有项目中最大的单项 SW 开销，且占 p061 增量的主要部分。

## 优化方向（未改代码，仅供参考）
- 对 `superworks_extractor.py` 的识别循环做剖析，确认 p061、p044 中的热点（如逐对匹配的嵌套循环）。
- 对 `superworks_semantics.py` 的 `_wire_index` 与逐实体遍历，检查是否可以复用 DXF 已有索引。
