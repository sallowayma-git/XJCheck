## 0. 结论

1. **33,602 条不是 33,602 个问题。** 它们描述的是 10,230 个未被覆盖的 DEV/TERM 端子（剔除装置内部后的未覆盖池 10,535 个的 97.1%）；每个端子平均约 3.3 条观察。覆盖池之外的 305 个未覆盖端子没有对应缺口行。
2. **分类结果（按优先级互斥）**：A 装置内部 14,273（42.5%）；B V1 已闭合 948；C V2 端点 5,241；D 跨页延续 1,380；X 非端子导线 3,676；E 残余 8,084。
3. **A 类（14,273）为什么没被装置内部判定吸收：** 装置内部判定（`device_internal_verdict`）已经在线级（DEV-INT 链接）和 pair 级生效，13,270 条的端子已被覆盖口径剔除。但缺口发射（`recognition_coordinator.build_resolution_issues`）只看线组上是否已有 pair。14,273 条中，**0 条**的线组上存在装置内部丢弃的 pair，因此发射路径从未调用装置内部判定。另有 1,003 条是段级判定为装置内部、线级链接未建立（多端导线、中途有其它触点或节点圆点），需线级复核后再关闭。
4. **B 类（948）为什么没闭合：** 同一段导线上确有 V1 非丢弃配对且身份一致（如 `7UD21 ~ 1n715`），但配对的线组 ID（GW 系列）与 SW 观察的线组 ID（GWSW 系列）不同，而覆盖判断按线组 ID 比较。948 条中 **0 条** 的 SW 线组上有非丢弃 pair，证实为 ID 不一致，而非图面无连接。
5. **C 类（5,241）V2 不能提供所需身份。** V2 绑定的端子文字在 4,970 条中与该端子自身身份相同，只是证实了端子；缺失的一侧是内部元件（光耦、继电器、线圈）的引脚，图面无脚号。271 条 V2 文字与端子自身身份不一致（如端子 1QD22 对应 V2 文字 1QD28），疑似错误绑定，不能作为闭合依据。
6. **主要根因（结构性）：** 25,798 条（76.8%）缺身份的一侧是内部元件或线圈。这与 PIN-S 的结论一致：图面多数内部元件引脚没有可核对的脚号，不是识别算法的缺陷。
7. **协调后离线估算（详见第 7 节）：** 若实施第 8 节的步骤 1–4（门禁、物理线段覆盖、延续覆盖、X 移出、F1 抑制），剩余 **14,213** 条。其中 **3,301** 条需先验证（A 线级复核 1,003、E_reg 引脚挂接 1,456、E_unreg_pin 文字挂接 842）后才能关闭；结构性待裁决约 **3,139** 条（端子排轨线与母线 T 接）；无脚号元件类约 **5,982** 条，应按页汇总而非逐条；**真正需要人工逐条核对的约 1,791 条**（开口端、未登记元件、文字未知、V2 冲突等）。
8. **覆盖率：** 严格口径（剔除装置内部）从 83.50% 变为 84.01%（仅 A 未剔除项剔分母 +B 闭合，覆盖 +36）；加入未登记端子文字闭合估算约 84.45%；若采纳“端子与内部元件无脚号连接计为覆盖事实”的口径，可达约 86.82%（需用户裁决，误报风险见第 6 节）。
9. **呈现建议：** 不应把 33,602 条逐条作为 review 问题呈现。建议改为端子级（约 1,800 条逐条）+ 页级汇总（结构类与无脚号类）+ 诊断产物（X 类与门禁关闭项）。实施顺序见第 8 节。

## 3. 逐类：证据、未闭合原因、协调方案与离线估算

### 3.1 A 装置内部（14,273）

**证据。** 13,270 条的装置端子已在 sw_port_coverage 中标记 `excluded_device_internal`（DEV-INT 线级链接已判定为装置内部并剔除分母）。目视 A1 组 5/5 为装置端子直接接本装置内部元件引脚（LED、线圈、开关），分类正确。

**为什么没被吸收。** 三层原因：
1. **发射门禁只看 pair。** `build_resolution_issues` 跳过 (文件, 页, 线组) 上已有非丢弃 pair 或装置内部丢弃 pair 的观察。装置内部丢弃（`_discard_device_internal_pairs`）只作用于已经存在的 pair。14,273 条的线组上**没有**装置内部丢弃的 pair（核验：0 条），故观察被发射。
2. **观察级身份缺失。** 内部元件一侧的 `unresolved_endpoint_identity | unresolved_pin_text` 使观察判为 INCOMPLETE，即使该观察的装置端子侧已经能被装置内部判定为“内部连接”。
3. **段级与线级不一致。** 1,003 条的段级判定为装置内部，但线级链接未建立（sw_device_internal_links 中仅 37 条在链接表中）。A2 组目视 5 例中至少 1 例（p000 S0008）在同一导线中途有节点圆点与另一触点；DEV-INT 的线级规则在导线上有多个其它端口时不计为装置内部（`excluded:wire_multi_end`）。多数未剔除项是否同属此类未逐条核对，需在步骤 5 中验证。因此门禁必须使用线级结论，不能只用段级结论。

**协调方案。**
- 引擎：SW 原生（装置内部判定本身即 SW 元数据加几何校验，无需 V1/V2）。
- 位置：`build_resolution_issues` 发射前；对每个观察，取其装置端子侧端口的线级结论（sw_device_internal_links 或 `device_internal_verdict` 的线级版本），满足则不发射，并在诊断产物中保留计数。
- 证据：线级链接已建立（relation = device_internal）；另一端为内部元件/线圈/未登记引脚，标签与装置标签相同。

**离线估算。** 关闭 13,270 条（不改覆盖率）；1,003 条需线级复核（若复核通过再关闭，否则保留为 review 并标注“装置内部候选，线级未确认”）。

### 3.2 B V1 已闭合（948）

**证据。** 目视 B 组 5 例：4 例同一物理线段上有 V1 配对（wire_component_mapping），配对的一侧为装置端子身份、另一侧为远端身份（如 `TF111 ~ 1n1519` 中 1n1519 为装置端子，TF111 为远端；`7UD21 ~ 1n715` 同理），远端端子文字位于线段另一端，与配对一致；1 例（p061 S0006）为 GND 与装置端子，V1 为 review，应归入 G-1（GND 公共地合法），不是缺口。

**为什么没闭合。** 覆盖判断按线组 ID（GWSW ↔ GW 不同），而 V1 配对与 SW 观察描述的是同一物理导线。0/948 条有同线组的非丢弃配对。

**协调方案。**
- 引擎：V1（已有配对，不需要新计算）。
- 位置：`recognition_coordinator` 的覆盖检查（`covered` 集合）改为按物理线段：段落在非丢弃配对的线组几何上（共线、重叠 ≥80%），且配对一侧身份与观察端身份一致。
- 证据：线段几何覆盖 + 身份一致；review 级配对只计 review。

**离线估算。** 关闭 948 条（其中 914 pass、34 review）；覆盖增量很小：这些端子大多已被其它 pair 占用，仅 36 个合格端子从未覆盖变为覆盖。

### 3.3 D 跨页延续（1,380）

**证据。** 目视 D 组 5/5：端子通过行延续（continuity_row）或跨页引用被覆盖，另一侧为未标脚号的内部元件（如 1I9D1、1I8D4 等行的线圈）。sw_cross_page_links 中 `covers_target=True` 的为 1,343 条；37 条为候选（sw_cross_page_candidates）。

**为什么没闭合。** 发射门禁不读取延续覆盖。

**协调方案。**
- 引擎：SW 原生（延续关系已由 SW 产出）。
- 位置：同 3.1 的门禁，增加“端口被 covers_target 延续覆盖则不发射”。37 条候选保留为 review。
- 注意：严格口径不计延续，含延续口径已计入，故不改变严格覆盖率。

**离线估算。** 关闭 1,343 条；保留 37 条候选。

### 3.4 C V2 端点（5,241）

**证据。** 目视 C_v2_redundant 组 5/5：端子（TERM、DEV 或 COIL）接未标脚号的内部元件（光耦输入、继电器触点、线圈、灯）。V2 绑定的文字与端子自身身份相同（4,970/5,241）。目视 C_v2_new 组 5/5 显示 V2 文字与端子身份不同（如 1QD22 对 1QD28；3-21QD45 对 3-21KK-1），疑似错绑。

**为什么没闭合。** V2 只在端子一侧给出身份，而缺失一侧是内部元件引脚，V2 不描述元件引脚的身份。

**协调方案。**
- 引擎：V2 能补的只有 271 条（且需先排除错绑）。
- 位置：`symbol_port_proposal` 的端口绑定只能给出端子身份，对内部元件无脚号的一侧无补证能力。
- 对 C_v2_redundant（4,970）的正确处理是：不作为“可闭合缺口”，而作为“元件引脚无脚号”的结构类，按页汇总（见第 8 节）。

**离线估算。** V2 实际可补证的为 0–271 条（C_v2_new 需逐条核验，可能全部是错绑）。4,970 条保持未闭合（结构类）。

### 3.5 X 非端子导线（3,676）

**证据。** 目视 X 组 5/5：两侧均为内部元件或线圈（线圈到线圈、触点到线圈、线圈到接地等），不涉及装置端子或端子排。覆盖分母只统计 DEV/TERM（sw_port_coverage 只含端子类），因此 X 类不影响覆盖率。

**协调方案。** 移出 R-RECOGNITION-GAP，改为诊断产物（sw_resolution_observations 已有）。

**离线估算。** 减少 3,676 条 issue，覆盖率无变化。

### 3.6 同身份多触点（E_port_both_ends 中的 152 条，并入 E）

**证据。** 两端身份完全相同（如同一端子的两个触点），与自环规则 `same_logical_identity_other_contact` 相同。

**协调方案。** 与现有 F1 自环规则一致，抑制为非缺口。

**离线估算。** 减少 152 条。

## 6. 误报风险与防护

| 方案 | 误报形态 | 防护 |
|---|---|---|
| A 门禁（13,270 + 1,003） | 外部导线被误判为装置内部（元件实际不属本装置） | 线级判定（单触点、标签相同、无其它触点/节点），1,003 条复核后再关闭；保留 DEV-INT 的 wire_multi_end 规则 |
| B（948） | V1 配对在同一段上但身份错误，闭合掩盖真错误 | 段几何重叠 ≥80%，且身份与 SW 端身份一致；review 级配对只计 review；GND 类按 G-1 单独处理 |
| D（1,343） | 延续关系被误用，掩盖真实跨页冲突 | 只计 covers_target=True；候选（37）保留 review；与 R-CROSS-PAGE-CONFLICT 互斥检查 |
| C_v2_new（271） | V2 文字与端子身份不同（错绑），若用作身份会产生伪连接 | 禁止用 V2 文字覆盖已有身份；只接受与端子身份一致或位置距离 ≤0.5 的绑定 |
| E_reg 引脚挂接（1,456） | 端子排轨线上的邻近标注被误配给引脚（错位一格） | 同 y（≤1.0）且标签与装置标签相同；逐例抽检（≥30 例）后再开放 |
| E_unreg_pin 文字（842） | 线号（数字）被误当脚号；标注不属于该引脚 | 文字须与块的标签族前缀一致（如 1KLP），且距离 ≤ 6；抽检 |
| E_rail_T / E_bus_T 的 T 接 | 线端落在不相关的母线或框线上，产生伪连接 | 仅在有节点圆点（sw_connect_dots，距离 ≤ 1.0）时视为连接；无点不闭合 |

## 8. 呈现建议与实施顺序

### 8.1 呈现

- **不建议**：33,602 条逐条 review 进入前端问题列表。
- **建议**：
  1. 逐端子 issue：约 1,800 条（第 7 节的“真正未知”集合），每个未覆盖端子一条，合并同端子的多个观察。
  2. 页级汇总：结构类（端子排轨线、母线 T 接）与无脚号元件类，按页给出计数与示例，不计入问题总数。
  3. 诊断产物：X 类、门禁关闭项、已由 V1 / 延续闭合项，保留在 sw_resolution_observations 与 details.json，不进入前端。

### 8.2 实施顺序（按风险从低到高）

| 步骤 | 内容 | 影响条数 | 覆盖率 | 风险 |
|---|---|---:|---|---|
| 1 | 发射门禁：装置内部线级结论 + 延续覆盖（不改覆盖口径） | 13,270（+1,343） | 无变化 | 低 |

| 3 | X 类移出 issue，进入诊断 | 3,676 | 无变化 | 低 |
| 4 | F1 自环抑制 | 152 | 无变化 | 低 |
| 5 | 线级复核 A 未剔除项（1,003） | 1,003 | 视结果，分母约 −345 | 中 |

## 9. 需用户裁决的问题

1. 呈现方式：是否采用第 8.1 节的端子级 + 页级 + 诊断产物三层呈现，而不是 33,602 条逐条。
2. G1T（端子排竖向轨线 T 接）：是否允许以“端子号标注 + 节点圆点”作为端子排去向证据（影响 E_rail_T 1,826 与 E_reg 1,456）。
3. 覆盖口径：元件无脚号的端子连接是否计为覆盖事实（S4，约 +2.8 pp，误报风险较高）。
4. C_v2_new（271）：是否将 V2 与端子身份冲突视为错绑并停止使用 V2 作为身份来源。
5. A 门禁的线级条件是否采用 DEV-INT 的规则（wire_multi_end 视为非装置内部）。
