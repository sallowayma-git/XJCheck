## 3. 关键发现

- SW 端口层帮不上：81 条缺侧端 6 单位内无 SW 端口、无 SW 符号、无 strip 行。
- SW 连接标签层能帮：30 条缺侧端 2.5–3.6 单位内有 SW 连接标签，文字即远端端子名（YD10、1-26DK2-2 &）。标签的 endpoint_identity 为 `1-26n-系统告警(NO3)` 一类组合串，不宜直接当端子号用，应取 text 的 value。
- 缺侧几何：p075 的 68 条缺侧端落在表格框线（LWPOLYLINE 边）或同行线段上，远端标识位于框外或同行；12 条无接触（元件引脚 4+4、p062 2、TS3000 2）。
- 旧链拒绝路径：`candidates.py:249` 与 `:1949` 对非数字文字返回 `not_numeric`；`pairs.py:286` `_scope_wire_logic_endpoint_candidates` 对右侧候选做非对称过滤，导致 PW0256 选错（见 S5）。
- 同一文字共享（8 条）：`rules.py:356` 发出 duplicate_text_line_claim，近邻线组全部报缺端，而非按距离归属。

## 4. 修复建议（通用，不按项目、不按取值）

- S1 SW 连接标签补缺侧：`superworks_extractor.py:777–812`，循环目前只对已有 component_mapping 旧链对生效（`old=[...]`），无旧链对则丢弃。改为：无旧链对时，若标签文字锚点（text insert）在某线组缺侧端 3.0 单位内，取 `label.text.value` 经 `_clean_sw_endpoint_value` 拆分后作为缺侧候选，注入 `pairs.py` 候选集（约 `:60–70`，`_accepted_sorted` 之前）。容差须 ≥3.0（实测 1.4–2.5）。
- S2 非数字端子名准入：`candidates.py:249` 与 `:1949`。对与线端同行、位于表格列外侧的非数字端子名（正则覆盖 串口\d+[+-]、脉冲\d+[+-]、IRIGB \d[+-]、GND/FG/N(-)、YD\d+、COM\d、\d-26(TD|DK)\d+），在数字端另一侧存在时给 semantic 通道，并沿用 `pairs.py:299` `_scope_schematic_semantic_endpoint_candidates`。中部功能标签（系统告警(NO3)、失步告警(NC2) 等）必须排除，见 §5 口径 a。
- S3 共享文字归属：`rules.py:340–360`。近邻重叠线组共享同一文字时，只保留到该文字端点距离最近的线组，其余不报缺端。
- S4 悬空/跨页判别：`pairs.py:~75`（`missing {side} candidate` 分支）。缺侧端 1.0 单位内无其它线段、多段线或块插入点（排除本线组，忽略 1 单位内的近平行线），且另一侧为线号 `\d+-?\d*n\d*` 时，status=discard，rationale=dangling_or_cross_page_wire。
- S5 候选非对称过滤：`pairs.py:286–296`。右侧无数字而左侧 `left_has_numeric=False` 时，直接删除右侧 wire_logic 候选。改为按距离与得分比较，不做无条件删除。PW0256 中 11（FZJ111，距 1.25，0.95）被删，选中距 8.7 的 12（0.7525）。影响至少 1 条，需重放验证。
- 不建议：把 `pairs.py:39` high_threshold 0.92 降到 0.80，会放过 9 条 LOW 之外的真实歧义。
