# GAP2-PAIR：GAP-2 的 3028 个未覆盖端口为何没有配对（只读调研）

分支 superworks-loop，基线 HEAD 556e999。只读：未改 `src/`、`tests/`，未 git。数据为 `.tmp/superworks_round19_full`（77 项目全量回放）。未读取、未删除 `.tmp/superworks_round20_full`。

## 0. 结论

1. **这些线组不是“误合并的空断口”，而是端子本体两侧被合并。** 3028 个端口中，3018 个（99.7%）与一个同标识、同 insert 的 SW 端口共处同一线组，两者间距恰为端子本体宽度 2.50（3006 个在 2.4–2.6 之间）。间隙内有该端子自身的尾号文字（如 `1n1502` 中的 `1502`，2991 个），没有圆点（0）。这个端子两侧各是一根导线：一侧接外部端子（已配对），另一侧接同装置的内部元件（无标识，本应是装置内部连接）或开口。GAP README 与 G2 README 把间隙文字判为“线号标注打断”，这一判断对端子本体不成立。

2. **为什么没有任何配对覆盖。** 三步叠加：
   - M1 线组构建：`line_groups.py::_can_merge_axis_intervals` 对 `gap <= 4.0` 无条件合并，不检查两端是否为端口。端子本体 2.5 落在该阈值内，两侧合为一条线组。G2 的文字守卫因尾号文字而未拆分（G2 只触发 1 次，即源于此）。
   - M2 配对：`superworks_extractor.py::extract_superworks_pairs` 只看线组的两个端点。P 一侧的段另一端是无标识内部元件（或开口），段判为 partial，不成对。Q 一侧的段由 GWSW 段正常成对（已有 pass）。
   - M3 装置内部链接：`superworks_device_internal.py` 在线组内 >1 个其它端口时记为 `excluded:wire_multi_end`，3028 个全部如此。

3. **中间端口被忽略不是主因。** 3025 个端口位于线组内部（非端点），但每个都是某条段的端点（观察记录 3028/3028 ≥1 条）。问题在于同一段的另一端，而不是端口本身没被看到。

4. **离线模拟的覆盖增量（方案 S，DEV-INT 侧分割 + 元件无标识守卫）：+2161 端口，+2.61 pp**（基线 68240/82680 = 82.54% → 70401/82680 = 85.15%）。对 R-MANY-TO-ONE、R-ONE-TO-MANY、R-CROSS-PAGE-CONFLICT、R-DUPLICATE-PAIR 的影响为 0（构造上如此，见 §5）。其中 1995 个来自本人群 2a，166 个来自其它装置端子签名。2b（972）无增量。

5. **链式配对（用户建议的方案 C）不建议。** 人群内 834 个新候选中全部横跨非端子断点（元件或标签），语料内 756 个新配对全部触及已有配对的标识（度数冲突）；重复配对 5129 个须去重。

6. **建议：先做 S（只在 DEV-INT 侧分割，不改线组与配对）。** 同时补上 DEV-INT 的元件无标识守卫（基线已有 97 条链接的元件带标识，属既有风险）。2b 的 972 个需另立根因调查（见 §6）。

## 1. 方法与口径

- 人群：`uncovered.parquet`（`GAP/tools/build_table.py` 生成，14440 行，与 DEV-INT 一致）中签名为 `内部元件(无身份) + 端子 + 装置端子`（2a，2056）与 `端子 + 装置端子`（2b，972）的装置端子。
- `tools/g2p_collect.py`：每个端口的线组上全部端口、沿线位置、是否在线组极端、覆盖观察记录、相关配对。
- `tools/g2p_sides.py`：在“端子本体间隙”处把线组切开，描述 P 一侧（远离伙伴 Q 的一侧）的端口、标签、间隙文字与圆点。
- `tools/g2p_classify.py`：三层分类（伙伴、侧类、配对状态）与方案 S 的守卫后链接标记。
- `tools/g2p_sim.py`：用生产函数 `build_device_internal_links` 在 round19 输入上重算。基线与 round19 存储的 `sw_device_internal_links` 77/77 项目逐条一致（`match_stored=True`）。方案 S 把线组按同标识端子本体间隙切开后重跑，链接只增不减（丢失 0）。链式方案 C 的相邻配对统计同时输出。
- `tools/g2p_gain.py`：增量、守卫与风险。所有关联均用 (项目, port_id) 复合键（port_id 在项目间重复，53493 个）。
- `tools/g2p_checks.py`：链式方案在人群与语料内的分类，以及 945 个开口端的探测。
- `tools/g2p_render.py`：分层抽样 20 例（2a 10：同标签内部元件 6、标签不可读 2、多端口 2；2b 10：开口 6、多端口 3、无伙伴 1；种子 20261011），DXF 渲染 10 张。
- 口径边界：**round19 = HEAD，早于未提交的 G1P 改动**（round19 无 `sw_unregistered_symb2`）。G1P 对本人群的影响见 §5.3。

## 5. 表示方法评估（round19 离线）

### 5.1 方案 S：DEV-INT 侧分割（推荐）

- 规则：在 DEV-INT 的线组划分中，若两个同 insert、同标识的装置端子端口位于同一线组上、间距 0.5–4.0、横向差 ≤ 1.0，则在两者之间切开；P 侧的线段形成独立的“导线”，再套用原 DEV-INT 规则。守卫：内部元件须无端点标识（否则该元件已参与线上的配对，形成冲突）。
- 增量（重跑 DEV-INT，77 项目）：新增链接 4337，丢失 0；守卫拦截 358（均为已配对端口，其元件带标识）；保留 3979。
  - 未覆盖的合格端口：**2161**（2a 1995、其它签名 166）。
  - 覆盖率：82.54% → **85.15%（+2.61 pp）**。
  - 已被配对覆盖的 6 例、已被 X2 连续性覆盖的 1812 例：不增加覆盖（双重证据，未发现矛盾）。
  - 每个端口至多 1 条新链接（`ports_with_multiple_new_links=0`）。
- 对 R-* 的影响：**0（构造上如此）**。DEV-INT 的链接只写入 `sw_device_internal_links` 与覆盖表（`superworks_artifacts.py`）；`src/` 中无规则读取 `device_internal_link_ids` 或 `consumed_with_internal`（grep 验证）。配对不变，因此 R-MANY-TO-ONE、R-ONE-TO-MANY、R-CROSS-PAGE-CONFLICT、R-DUPLICATE-PAIR 计数不变。
- 与 G1P 无重叠：G1P 只针对单端导线，S 只针对多端线组。若合并，覆盖增量为 +1851（G1P，GAP 估计）+ 2161（S）= 约 87.4%（估算，未联合重跑）。

### 5.2 方案 C：链式相邻配对（用户建议，不推荐）

| 口径 | 人群（3028） | 语料（77 项目） |
|---|---|---|
| 同标识相邻（自配对，丢弃） | 3052 | 5367 |
| 与已有配对重复 | 2496 | 5129 |
| 新候选，横跨非端子断点（元件/标签） | 834（2a 199，2b 635） | 736 |
| 新候选，端子本体间隙（≤4） | 0 | 20 |
| 新候选且触及已有标识（度数冲突，≈R-MANY-TO-ONE/ONE-TO-MANY 风险） | — | 756（全部） |

- 问题：相邻端口之间可能隔着一个元件或标签（如 p027 的 `5n1521` 与 `5KD7` 之间有 `5C4LP1`），链式配对会跳过元件，形成错误配对。
- 覆盖增量：人群内 834 个新候选若被接受会计入配对覆盖，但全部横跨元件或标签，不能判为直连，因此不作为增量计入。与 S 相比，S 的增量来自可判定的装置内部连接，不依赖相邻关系。
- 未离线模拟 R-CROSS-PAGE-CONFLICT（需回放规则引擎）。

### 5.3 线组级拆分（G2 修正版）与 G1P

- 线组级拆分（G2 的修正）：配对层面没有增量。P 的另一侧不是 SW 端口，Q 侧段已成对。它会改变旧线组的配对（如 `PW0144` 的 discard），风险高于 S。
- G1P（未登记块引脚）：对 945 个开口端做块顶点探测，**0/945** 与块顶点重合，G1P 对本人群无增量。

## 7. 实施建议

1. **S（DEV-INT 侧分割 + 元件无标识守卫）**：在 `superworks_device_internal.py::build_device_internal_links` 中，在多端检查之前按端子本体切开线组；保留线组与配对不变；新增字段（如 `split_partner_port_id`）以便审计。

5. **修正文档**：GAP README §5.2 的 G2 增量（1604）与 G2 README 的结论（文字断口=标注打断）需改为本报告结论。G2 的文字守卫在拆分前须排除端子自身的尾号文字。

## 8. 风险
